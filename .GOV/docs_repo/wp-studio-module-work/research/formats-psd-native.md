## 2. Gaps for hsk-studio-package

- GP1 ZIP64 codec. Recommend in-house STORE-only ZIP64 writer + bounded reader (deps: crc32fast), not the `zip` crate. Evidence: zip 9.0.1 (2026-10-10, MSRV 1.88) default features pull C `zstd`, bzip2, aes; docs.rs ZipArchive documents no entry-count/size limits and is silent on duplicate names (UNVERIFIED behaviour); it reads the central directory and ignores local headers (differential risk: Python CVE-2025-8291 ignored the ZIP64 locator offset; uv advisory on streaming-vs-CD parsers). rc-zip 5.4.1 (2025-11-19): sans-IO, read-only, ZIP64, pure Rust; async_zip 0.0.19 is pre-1.0. Fallback if builders insist on reuse: zip with default-features=false + `deflate-flate2-zlib-rs`, but first parse EOCD/ZIP64 locator and reject entries/cd_size/cd_offset beyond Limits before `ZipArchive::new`, then cross-check CD vs local headers.
- GP2 Entry model. One STORED entry per content-addressed blob `blobs/<algo>/<hex>` (dedupe free; PhotoCraft does `tiles/<blake3>.zst`, 256x256 tiles, STORE entries). Tile layout stays in graph JSON (Folio TileRef), not the zip directory. CD cost is ~46 B fixed + name + ZIP64 extra per entry (APPNOTE, not re-fetched): 1M tiles ~ 100-150 MB, so enforce MAX_ENTRIES and defer "pack entries" (OpenEXR-style offset table per part) to v2.
- GP3 Tile codec registry (codec id per blob in a manifest blob table with raw_size, stored_size, crc32, digest). v1 set: `raw`; `zstd` via ruzstd 0.9.0 (pure Rust; decoder complete, encoder: docs.rs marks Default/Better/Best "UNIMPLEMENTED" while README lists them -> treat only `Fastest` as usable; PhotoCraft store.rs:30 uses Fastest; README: decoder 1.4-3.5x slower than C); optional `lz4` via lz4_flex 0.14.0 (safe by default, README documents no output-size cap, so always pass exact expected size). C `zstd` 0.14.2 (zstd-sys) only behind a feature if ratio proves necessary. Rejected for v1: per-tile lossless WebP (image-webp 0.2.4 pure Rust but 8-bit only, cannot hold u16/f32), per-tile JXL (only decoder crates found: jxl-oxide 0.12.6; no pure-Rust encoder found). Add a byte-shuffle/delta pre-transform for f32/f16 planes as a codec option; benefit UNVERIFIED, builder measures once on a Pigment rgb_f32le tile. Prior art backing "compress per tile, store ZIP entries uncompressed": Krita .kra moved from KZip to per-tile LZF (64x64 tiles, `x,y,LZF,size` records, 2010 wiki), Procreate = ZIP of `{uuid}/{col}~{row}.chunk` (LZO or LZ4, sources disagree).
- GP4 Digest. Identity = SHA-256 (matches prep `blobs/<sha256>`; sha2 0.11.0 already pinned by Prism); ContentDigest.algorithm is a free string so blake3 can be added later. blake3 1.8.7: default x86_64 build uses hand-written asm via build.rs/cc; feature `pure` forces pure Rust (PhotoCraft uses `pure`). ZIP-mandated CRC32 is separate.
- GP5 Atomic save on Windows. Port the pattern from PhotoCraft crates/format/src/atomic.rs (MIT OR Apache-2.0): create_new temp in same dir, sync_all, rename over with exponential backoff on PermissionDenied (AV/indexer), Unix dir fsync, injectable `AtomicFs` for fault injection at every step. std::fs::rename: Windows 10 1607+ uses FileRenameInfoEx (POSIX semantics) if the FS supports it, else MoveFileExW; std docs do not state atomicity, so a real Windows interrupted-save test is mandatory (STUDIO-DOC-PROP-003). `atomic-write-file` 0.3.1 exists (mechanism UNVERIFIED). Package defines the sink trait (write temp -> validate -> commit_replace -> keep last-good); std::fs impl behind a feature; ArtifactService port impl is the host's.
- GP6 Versioning/forward compat. manifest `format_version` + `min_reader_version`; newer major = typed TooNew (PhotoCraft FormatError::TooNew pattern); unknown records -> `quarantine/<sha256>` + provenance in manifest; `mimetype` first entry stored (OpenRaster rule, verified). Prior art: OpenRaster (zip, stack.xml, PNG layers, mergedimage.png), .fig (8-byte prelude `fig-kiwi` + u32 version + schema chunk + data chunks), layered TIFF (tag 37724 embeds a PSD-style block), OpenEXR multipart (per-part chunk offset tables); Affinity and Pixelmator internals are undocumented (UNVERIFIED).
- GP7 Negative tests to require: duplicate canonical path (case-fold/unicode), traversal, absolute/device names (CON, `\\?\`), ZIP64 locator mismatch, CD vs local-header mismatch, prepended/trailing/concatenated zips, EOCD count vs real count, sizes that lie (enforce while streaming), CRC and digest mismatch, cyclic references, kill between temp-write and rename.

## 3. Gaps for hsk-studio-interop-psd

- GI1 Parser facts (Adobe spec, verified): 8BPS v1 / 8BPB v2; <=56 channels; 30,000 px (PSD) / 300,000 px (PSB); depth 1/8/16/32; modes 0 bitmap,1 gray,2 indexed,3 RGB,4 CMYK,7 multichannel,8 duotone,9 Lab; big-endian. PSB widens layer/mask section, layer-info, channel lengths and RLE row counts (4 -> 8 / 2 -> 4 bytes); 8-byte block lengths for LMsk Lr16 Lr32 Layr Mt16 Mt32 Mtrn Alph FMsk lnk2 FEid FXid PxSD; 16/32-bit layer data sits in Lr16/Lr32/Layr (inner layout not in the fetched text; photocraft-psd implements it). Compression 0 raw, 1 PackBits RLE, 2 ZIP, 3 ZIP+prediction. Layer count < 0 => first alpha holds merged transparency. Blend ranges = composite gray + per channel src/dst entries (8 values per channel, matches STU-RAS-159). lsct 0-3 (+blend key, subtype), lfx2 (descriptor v16), SoLd v4, vmsk v3, Txt2 raw engine data, clbl/infx/knko/tsly flags. Resource 1039 ICC, 1041 untagged flag, 1057 Version Info with `hasRealMergedData`. CMYK stored inverted (255 = no ink): only secondary source (Apache Commons Imaging comment), verify with oracle.
- GI2 Merged composite. With Maximize Compatibility off Photoshop writes an all-white placeholder and hasRealMergedData=0 (Adobe community post; spec: composite is not created). Rule: composite is an oracle only when the flag is 1; otherwise classify `NO_ORACLE` and re-composite from layers.
- GI3 Why third-party renders differ (evidence): missing/placeholder composite (ZBrush, Lightroom error text); layer effects are not baked into layer channels (GT Designer needs rasterized, ImageMagick cannot); Pass Through groups read as Normal (Krita, Aspose forum); GIMP clipping: Photoshop stops at first non-clipped layer, and GIMP legacy-mode change broke "Blend Clipped Layers as Group" (gitlab gimp #10505/#10498); default blending is in gamma-encoded values, "Blend RGB Colors Using Gamma" is a global app setting, not per document (Adobe forum); type uses text gamma 1.45 (PhotoCraft psblend.rs); 16-bit is 0..32768 internally (Chris Cox, Adobe forum 2011, not official); Photoshop-only modes (linear light, vivid light, hard mix, divide, subtract, darker/lighter colour, dissolve) are unpublished and were reverse engineered (SVG WG archive) - PhotoCraft derived Vivid Light and Hard Mix edge cases from psd-tools blend-modes fixtures; psd-tools itself skips dissolve, most effects, approximates Lab/duotone; feathered masks wrong in Lightroom/macOS Preview.
- GI4 Priority-ordered requirements for Studio to match Photoshop display: (1) composite semantics: pass-through groups (group default), clipping incl. blend-clipped-as-group (clbl), mask stack (raster, vector, group, density/feather, disabled), fill-vs-opacity, Blend-If split sliders, knockout, infx/tsly; (2) Photoshop-exact blend functions and edge cases in document-encoded space, straight-alpha PSD data, 16-bit rounding; (3) trust Photoshop-rendered cached pixels for text, smart objects, shapes as display truth and preserve Txt2/SoLd/lnk2/vmsk bytes, plus render lfx2/lrFX effects in the compositor (not in channels); (4) colour: ICC 1039/1041, per-mode (CMYK, Lab, gray, duotone, multichannel, indexed) to display path, intent/black-point, Color Settings state recorded; (5) byte-stable preservation of unknown blocks/resources/padding with typed loss receipts, never default an unknown blend to Normal (PHOTO-F-004). Dissolve and other non-reproducible features go to the loss report.
- GI5 Reuse vs own parser. Reject: `psd` 0.3.5 (last release 2024-01-04, read-only, open issues: panic on crafted file #70, no PSB #2, no ZIP #68); zune-psd 0.5.1 (base layer only); rawpsd 0.2.2 (8-bit, no PSB, CS6 target); ffpsd (C++ bindings, v0.0.1); ag-psd 0.3.0 Rust port (README: "vibe-coded", not audited, CMYK rejected) - reference only. Adopt-by-fork: photocraft-psd (MIT OR Apache-2.0, clean-room from Adobe spec, 27 files/11.8k lines, forbid(unsafe), byte-stable round trip, raw unknown blocks, all 4 compressions, PSB, lazy decode, limits, truncation-sweep tests; deps thiserror+flate2) as the byte layer inside interop-psd, keeping NOTICE, swapping in workspace-pinned deps and Accord budgets (vendoring precedent: Type crate). Source: gov_runtime/tools/studio-craft-source-cache/photocraft-175603a644f10d2e8c61f82a63f7c2659c71dc47/crates/psd. PhotoCraft's own CI floors vs Photoshop composites at 2/255 premultiplied tolerance: 133/256 (Photoshop corpus), 146/170, 236/309 - the "Craft shows PSDs differently" baseline Studio must beat.

## 5. PSD display oracle (public specs + black-box observation only; no decompilation of Adobe software)

- Installed: Adobe Photoshop 2026, Photoshop.exe FileVersion 27.11 (20260929.r.26 8c16e56); Presets/Scripts ships ExtendScript .jsx files (Export Layers To Files, Image Processor) so ExtendScript is available in this build. Existing script pattern: reference/studio_app_feature_research/_installed_export_scripts/photoshop-export-inventory.jsx (run via File > Scripts > Browse, writes JSON, uses alert()).
- Tier 0, no Photoshop launch: the merged composite inside any Photoshop-saved PSD with hasRealMergedData=1 is the reference render. Public corpora: storytold/photocraft-corpus (256 small PSDs, Photoshop 27.10.0 on macOS via ExtendScript, MIT OR Apache-2.0: 30 smart-filter, 37 layer-style, 54 type, 135 adjustment files across RGB/Gray 8/16/32, CMYK 8/16, Lab 8/16; no ICC embedded; no dedicated blend/group/mask folders; ~5.4 MB packed) and psd-tools fixtures (blend-modes/*.psd). Downloading either needs Operator approval (name source, size).
- Tier 1 gap corpus, authored once in installed Photoshop (opens a foreground window => Operator approval per GLOBAL-BUILD-053; Operator runs the script once, ~15 min, no preference changes). Cases (<=320x320, ~50 files): C1 27 layer-settable modes x {layer, normal group, pass-through group} at 8-bit, key subset at 16/32-bit (32-bit mode set narrows, STU-RAS-149); C2 nested groups with non-normal/adjustment inside, group opacity/fill/mask; C3 clipping (2 clipped layers, clbl on/off, clipped adjustment, clip to group); C4 raster/vector/group masks, density, feather, disabled, unlinked; C5 opacity vs fill with effects, infx, tsly, knockout shallow/deep, Blend-If split sliders on gray and per channel; C6 each effect kind alone + stack + global light; C7 colour: sRGB, Display P3, ProPhoto, Adobe RGB, untagged (res 1041), Gray, CMYK, Lab, duotone, multichannel, indexed, bitmap, mismatched-profile placed object; C8 16-bit ramp, 32-bit HDR ramp (>1.0), semi-transparent edge pixels; C9 same doc with Maximize Compatibility on/off (confirms 1057 flag + white placeholder); C10 PSB boundary sparse >30,000 px; C11 file with blocks Studio does not parse (smart-object filters, video) for byte-stable round-trip.
- Mechanism: new `psd-oracle-build.jsx` (kept in wp-studio-module-work/oracle/, not in reference/) builds each case with the DOM (ArtLayer.blendMode, LayerSet) and Action Manager for what the DOM lacks (clipping, Blend-If, effects), saves `<case>.psd` with Maximize Compatibility and `<case>.reference.tif` (TiffSaveOptions, uncompressed, embed profile; forum: embedColorProfile can reset compression, set compression after; DOM PNGSaveOptions cannot embed ICC, so TIFF is the reference for 8/16/32-bit) plus `<case>.json` (case_id, features, expected Studio disposition editable/cached/loss, app version, Color Settings snapshot, fonts). Output only under Handshake_Artifacts/WP-KERNEL-STUDIO/psd-oracle/ (CX-984), never Desktop.
- Not usable / unverified: `Photoshop.exe -r` and COM `DoJavaScriptFile` unattended runs (no official confirmation found; UNVERIFIED); screenshots (display-profile transform); changing Color Settings (global; needs Operator approval, record the state instead); Photoshop cloud API (account-gated adapter). Fallback if the script fails: Operator does Save As PSD (max compatibility) + Save a Copy TIFF per case from a case list in the manifest.
- Comparer: neither interop-psd nor package may depend on composite, so propose a steward-owned non-module tool crate under tools/ (workspace has tools/workspace-probe.rs) that loads PSD via interop-psd, composites via composite/render-cpu, compares to the reference. Metric (PhotoCraft precedent): premultiplied max abs diff over pixels visible in either image <= 2/255, plus % bad pixels, per-feature failure map, floors only ratchet upward; 16-bit compare at 1/32768 granularity (UNVERIFIED). Result goes into the render_comparison_result receipt field (50-proprietary plan). Edit-after-open (re-render without Adobe caches) is a separate proof (PHOTO-F-002).
